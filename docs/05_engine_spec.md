# Спецификация движка v0.1

Связь решений из `04_project_mbc_anxiety.md` с кодом в `src/mbc/`.
Для каждого параметра указано, на чём он основан: **источник** (взят из литературы),
**практика** (принят в крупной системе, например NHS) или **эвристика** (наше допущение,
требует проверки на данных).

## 1. Шкалы — `measures.py`

| Шкала | Пункты × диапазон | Порог «случая» | Надёжное изменение | Основание |
|---|---|---|---|---|
| GAD-7 | 7 × 0–3 | 8 | 4 | практика NHS Talking Therapies |
| PHQ-9 | 9 × 0–3 | 10 | 6 | практика NHS; пункт 9 → протокол безопасности |
| PHQ-8 | 8 × 0–3 | 10 | не задано | источник (Kroenke et al., 2009) — сверить |
| OASIS | 5 × 0–4 | 8 | не задано | источник (Campbell-Sills et al., 2009); RCI — рассчитать на русских данных |
| WSAS | 5 × 0–8 | не задан | не задано | — |
| CGI-S | 1 × 1–7, оценка терапевта (`rater = "clinician"`) | не задан | не задано: порог сдвига передаётся явно | Guy, 1976 — сверить; только для слоя расхождений (раздел 10) |

Границы тяжести — тоже пороги и тоже с источником (`severity_source`): GAD-7 5/10/15 —
Spitzer et al., 2006; PHQ-9 5/10/15/20 — Kroenke et al., 2001. Отчёт выводит источник
рядом со статусом.

Шкала клинициста (`rater = "clinician"`) не проходит в API самоотчёта: `build_report`, `outcome`,
`rule_based_flag` и `combined_outcome` её отклоняют, а `threshold_from_sample` для шкалы из одного
пункта принимает только ICC ретеста — α и ω для одного пункта не определены.

Тексты пунктов в репозитории не хранятся. Все пороги получены на англоязычных
выборках; флаг `verified_ru_thresholds = False`, пока они не пересчитаны на русских данных.

## 2. Скоринг — `scoring.py`

- Ответы проверяются на число, тип и диапазон.
- По умолчанию любой пропуск → `total = None` (строгий режим).
- Пропорциональный пересчёт (`max_missing > 0`) — **эвристика**; включается осознанно
  и помечается флагом `prorated`.
- Округление пересчитанного балла — арифметическое: ровно .5 вверх (как ROUND в Excel),
  в целых числах. Встроенный `round()` округлял .5 к чётному: 10.5 → 10, но 17.5 → 18.
  Выбор — **решение проекта**: терапевт, пересчитывающий балл вручную или в Excel, получит
  то же число. Правило пересчёта в NHS Talking Therapies не сверено — сверить с первоисточником.

## 3. Надёжное изменение — `reliable_change.py`

Jacobson & Truax (1991) — **источник**:
`SEM = SD·√(1−r)`, `S_diff = √2·SEM`, порог `= 1,96·S_diff`.

Выбор коэффициента надёжности — методологическое решение: при SD = 5 замена
α = 0,92 на ретестовую r = 0,83 увеличивает порог с ≈3,9 до ≈5,7 балла
(проверено тестом `test_choice_of_reliability_moves_threshold`).

### Порог по своей выборке — `threshold_from_sample()`

| Правило | Основание |
|---|---|
| SD и надёжность — на одной и той же выборке, иначе SEM неверна. Проверяется: обязательный `reliability_n` должен совпасть с n полных замеров; для ICC ретеста другая выборка допустима (анализ чувствительности) и помечается в источнике | решение автора |
| Выборка — первые замеры, по одному на человека; только полные: неполные и пересчитанные из-за пропусков исключаются и считаются в `excluded` | решение автора |
| SD выборочное (n − 1) | решение автора |
| Вид коэффициента (`kind`) — обязательный параметр: ω наблюдаемой суммы, α или ICC ретеста | выбор не должен быть неявным |
| Для OASIS: основной — ω наблюдаемой суммы (по ковариациям сырых баллов) на той же клинической подвыборке, что и SD; ICC ретеста — анализ чувствительности | пререгистрация, раздел 6; открытый спор: Jacobson & Truax 1991; Evans et al. 1998; McAleavey / Hays — сверить с первоисточниками |
| Ординальный ω (по полихорическим корреляциям) для порога не используется и в `kind` не предлагается | Chalmers, 2018: ординальная альфа описывает не наблюдаемую сумму — сверить с первоисточником |
| Порог в баллах — `ceil(порог − 1e-9)`: 3,92 → 4, 4,0 → 4, 4,01 → 5; шум 4.000000000000001 → 4 | решение автора |
| `classify_change` сравнивает с тем же допуском 1e-9 — для целых изменений дробный порог и порог в баллах дают одно и то же (тест-свойство) | следствие предыдущего правила |
| Жёсткого минимума n нет (кроме n ≥ 2); n — отдельное поле результата, отчёт печатает «порог рассчитан на выборке n = …» | решение автора |

Ориентир объёма: клиническая подвыборка — не меньше 100, ретест — 50–100
(`docs/04_…`, раздел 6, этап 5; пререгистрация, раздел 3) — **сверить с COSMIN**.
Доверительного интервала для самого порога пока нет — задача в ROADMAP.

## 4. Клинический статус — `status.py`

Логика NHS — **практика**, на уровне одной шкалы:

| Статус | Условие |
|---|---|
| Надёжное ухудшение | рост не меньше порога (проверяется первым, даже ниже порога «случая») |
| На старте ниже порога | X1 < порога «случая» |
| Надёжное выздоровление (reliable recovery в терминах NHS) | надёжное улучшение и X2 < порога «случая» |
| Надёжное улучшение | снижение не меньше порога, X2 ≥ порога |
| Нет надёжного изменения | всё остальное |

Если у шкалы нет порога надёжного изменения, функция требует передать его явно —
молча подставлять чужой порог нельзя.

### Статус по двум шкалам — `combined_outcome()`

Логика NHS Talking Therapies — **практика** (Clark, 2018, Annu Rev Clin Psychol 14:159–183;
источник указан автором, формулировки сверены им). Результат — независимые флаги, а не одна
категория: сначала надёжное изменение по каждой шкале, потом флаги по формулам.

| Флаг | Формула (GAD-7: «случай» ≥ 8, изменение 4; PHQ-9: «случай» ≥ 10, изменение 6) |
|---|---|
| `at_caseness_start` | GAD₁ ≥ 8 или PHQ₁ ≥ 10 |
| `recovery` | «случай» на старте и GAD₂ < 8 и PHQ₂ < 10; `None`, если на старте не «случай» |
| `any_down` / `any_up` | надёжное снижение / рост хотя бы по одной шкале |
| `reliable_improvement` | `any_down` и не `any_up` |
| `reliable_deterioration` | `any_up` и не `any_down` |
| `mixed` | `any_down` и `any_up` — разнонаправленное изменение не прячется |
| `reliable_recovery` | `recovery` и `reliable_improvement`; `None`, если на старте не «случай» |

Отличия от статуса по одной шкале — намеренные: ухудшение не проверяется первым,
«на старте ниже порога» не маскирует остальные флаги. Изменение по каждой шкале
доступно отдельно (`changes`).

`finished_course` — обязательный параметр: NHS считает статус по завершённым курсам.
При `False` статус промежуточный (`interim=True`) и со статистикой NHS не сопоставим —
так он и должен подписываться в отчёте.

Правило для отчёта (при интеграции): надёжный рост по любой шкале (`any_up`) — красный
сигнал терапевту независимо от флагов NHS. Флаги NHS — для сопоставления с их статистикой,
сигнал терапевту — для безопасности клиента; у них разные задачи.

## 5. Траектория — `trajectory.py`

Уровень 4а, **эвристика**:

- красный — надёжное ухудшение относительно старта;
- жёлтый — к 4-й сессии (параметр `check_by_session`) нет надёжного улучшения у клиента, начавшего выше порога;
- зелёный — иначе;
- «недостаточно данных» — меньше двух замеров.

Правило не валидировано. План замены: кривые ожидаемого ответа по стартовой тяжести
(4б), затем прогноз по похожим клиентам (4в). Метрики качества сигнала при замене:
доля пойманных итогово ухудшившихся, доля ложных тревог, номер сессии срабатывания.

## 6. Безопасность — `safety.py`

- PHQ-9, пункт 9: ответ > 0 → сигнал; пропуск → сигнал «уточнить».
- Модуль не оценивает риск и не формирует рекомендаций. Действия по сигналу и ресурсы
  помощи для клиента задаёт конфигурация сервиса и протокол терапевта.
- Без готового протокола реагирования в продукте используется PHQ-8.

## 7. Карта триггеров — `triggers.py`

Запись эпизода по схеме ABC: интенсивность 0–10 · где · с кем · что было за час до ·
мысль · реакция · длительность · сон · кофеин · алкоголь накануне · недомогание.

| Решение | Основание |
|---|---|
| Прогресс паттерна = интенсивность и доля избегания, не частота | следует из механизма экспозиции (наш вывод) |
| Избегание = бегство, избегание, охранительное поведение, поиск перестраховки; обращение за поддержкой — не избегание | КПТ-модели тревоги |
| Паттерн — от 3 эпизодов | эвристика |
| Порог сна 6 часов для пометки «телесный фактор» | эвристика |
| Комбинации измерений — только по явному флагу | защита от множественных сравнений |

## 8. Гипотезы ИИ — `hypotheses.py`

Контракт вывода языковой модели (сама модель в v0.1 не вызывается):
формулировка, идентификаторы записей-доказательств, «support из total»,
**обязательная альтернатива**, вопрос для проверки на сессии, статус
«предложена → подтверждена / отклонена» (решение принимается один раз).
Шаблон промпта — `prompts/hypothesis_prompt.md`.

Проверка вывода — в два шага. `Hypothesis` проверяет форму: есть опора, альтернатива
и вопрос, support не больше total. Но форма не гарантирует, что опора существует:
гипотеза со ссылкой на несуществующую запись проходит её без ошибки. Поэтому
`verify_evidence()` сверяет гипотезу с записями: каждый id из доказательств есть среди
записей и не повторяется; total не больше числа записей за период; если передан
контекст (паттерн) — доказательства принадлежат ему, а total равен числу его записей.
Все несоответствия перечисляются в одной ошибке.

Чего сверка не ловит: запись существует и принадлежит контексту, но не подтверждает
формулировку (например, интенсивность низкая). Смысловое соответствие проверяет терапевт —
для этого гипотеза и показывается со списком записей и альтернативой.

## 9. Отчёт для терапевта — `report.py`

Адаптер над разделами 4–7: новой статистики не добавляет, только собирает результаты
и подписывает, где эвристика и откуда пороги. Отчёт только для терапевта — не для
передачи клиенту и не диагноз. Два слоя: `build_report()` → данные, `render_text()` → текст.

| Решение | Основание |
|---|---|
| Вход — пары (сессия, Score) одной шкалы; смешение шкал → ошибка | контракт отчёта |
| Незасчитанный замер (`total = None`) в траекторию и статус не идёт; если не засчитана первая сессия, отчёт называет новую базовую линию | контракт отчёта |
| Пересчитанный пропорционально замер идёт в расчёт с пометкой; отдельное предупреждение, если пересчитан базовый | пересчёт — **эвристика** (раздел 2) |
| Отчёт не вызывает `check_safety`: получает готовые сигналы с номером сессии; три состояния шапки — сигналы есть / проверено, сигналов нет / проверка не проводилась | раздел 6: модуль безопасности только поднимает сигнал |
| Пустой список сигналов означает «проверено» только после шкалы с пунктом безопасности (PHQ-9); для GAD-7 и PHQ-8 передаётся `None` | у этих шкал нет пункта безопасности |
| Порог, переданный вручную, требует источника; в тексте видно, какой порог шкалы он заменил | каждый порог — с источником |
| Топ-N паттернов — в порядке `find_patterns` (по числу эпизодов); урезание показывается («показано k из m») | **эвристика** отбора: ранжировать по интенсивности на 3–6 точках — ранжировать шум |
| У каждой дельты — своё n; доля избегания — по записям с отмеченной реакцией; промежуточные недели показываются | прозрачность: гладкий текст не должен выглядеть надёжнее данных |
| Телесные факторы считаются среди записей с заполненными полями: «нет данных» ≠ «нет фактора» | эпистемическое правило проекта |
| Правило светофора расписано в тексте; «к сессии N» — номер сессии терапии, а не число замеров от базовой линии | раздел 5, уровень 4а — **эвристика** |

## 10. Слой расхождений — `discrepancy.py`

Самоотчёт клиента × оценка терапевта (CGI-S). Спецификация, решения автора и отличия кода от
текста — `06_discrepancy_spec.md`. Расхождение — тема для разговора, не вердикт; блок для терапевта,
поставившего оценку, агрегатов по терапевту нет. На светофор и шапку безопасности не влияет.

| Решение | Основание |
|---|---|
| Сравниваются направления изменений, каждая шкала — сама с собой; уровни GAD-7 и CGI-S не сопоставляются, и блок пишет, что устойчивое расхождение уровней не видно | таблицы соответствия уровней нет (не найдено — это не данные против) |
| Клиентская сторона — из готового `ClientReport`: та же база, тот же порог и источник, что у статуса; база блока другая — строка-пояснение | клиентская сторона обязана совпадать со светофором |
| Сторона терапевта — `Direction` (лучше / сдвиг меньше порога / хуже), слово «надёжное» не применяется | порог для одного пункта — **эвристика**: 2 балла основной, 1 — анализ чувствительности |
| `cgi_threshold` и `cgi_threshold_source` обязательны, без значений по умолчанию; `SampleThreshold` — только ICC ретеста по CGI-S | правило 3 |
| Одна сторона на пороге, другая с тем же знаком ниже порога — согласие ниже порога, не расхождение | «нет надёжного изменения» ≠ «без изменений» |
| Направление, которое у границы шкалы недостижимо, не определяется; причина печатается | иначе мягкие и тяжёлые клиенты давали бы расхождения по построению |
| Окна: база → текущая; предыдущая пара → текущая — только для ухудшения клиента, если от базы его нет | рецидив после ранних успехов от базы не виден |
| `OPPOSITE` и `CLIENT_WORSE_UNSEEN` выводятся всегда, остальные — свёрнуто, пока не держатся двух сравнений подряд | случай Hannan et al., 2005 — сверить |
| При надёжном ухудшении клиента первая строка записи — указатель на светофор и шапку безопасности | правило 5: указатель, не оценка риска |
| Слепота — по отметкам времени; строка «оценок после просмотра самоотчёта: k из m» — во всех состояниях блока | якорение создаёт ложное согласие, а согласие не выводится |
| Альтернативы — в модальной форме, первой — буквальное прочтение; фактические (экспозиция) — только при подтверждении картой триггеров | тексты — черновик до правки автора; лексический тест не заменяет вычитку |
| CGI-S не входит в правило «надёжный рост по любой шкале — красный» | это не самоотчёт; решение автора |

## 11. Чего в v0.1 нет — намеренно

- Telegram-бота и хранения данных: нужны юридическая проверка и протокол безопасности.
- Вызовов языковых моделей: нужны обезличивание и решение по трансграничной передаче.
- Кривых ожидаемого ответа: нет данных.
