# CLAUDE.md — mbc-anxiety-ru

## О проекте

MBC-инструмент (measurement-based care) для русскоязычной КПТ-практики с тревогой:
регулярный замер исхода, индекс надёжного изменения, сигнал «клиент идёт хуже ожидаемого»,
персональная карта триггеров, ИИ-гипотезы для терапевта. Плюс исследовательский трек —
межкультурная адаптация шкалы OASIS по стандарту ITC (2017).

Автор — Олег, психолог (КПТ), строит позиционирование на стыке психологии, ИИ и продуктовых
исследований. Цель репозитория — рабочий движок и портфолио-кейс.

@ROADMAP.md

## Как работать с автором

- Общение на русском. Идентификаторы в коде — английские, docstrings и комментарии — русские.
- Работать поэтапно: предложить этап и состав работ → дождаться подтверждения → сделать →
  зафиксировать решение в журнале решений в `ROADMAP.md`.
- Обратная связь прямая, без смягчений: общая оценка → разбор по блокам → почему это важно.
- В документах размечать утверждения: [замер] / [интерпретация автора] / [моя склейка];
  статус доказательности — твёрдо / умеренно / шатко. «Нет данных за» ≠ «есть данные против».
- Не выдумывать источники, числа, DOI. Если не уверен — писать «сверить с первоисточником».

## Жёсткие правила

1. **Никаких данных клиентов или участников** в репозитории. Папка `data/` в `.gitignore`.
   Демонстрации и тесты — только на синтетических данных с явной пометкой.
2. **Никаких текстов пунктов шкал** (OASIS, WSAS и любых других) до получения разрешений.
   В коде — только структура: число пунктов, диапазон, пороги.
3. **Каждый порог — с источником** в `measures.py`. Пороги англоязычных выборок помечены
   `verified_ru_thresholds = False`. Не подставлять чужой порог молча: если его нет —
   функция требует передать его явно.
4. **ИИ-слой никогда не обращается к клиенту и не ставит диагнозов.** Вывод модели обязан
   проходить валидацию `mbc.hypotheses.Hypothesis` (доказательства + альтернатива) и сверку
   `mbc.hypotheses.verify_evidence()` с записями (опора существует, total совпадает с контекстом).
5. **Безопасность:** `safety.py` только поднимает сигнал. Не добавлять туда оценку риска
   или рекомендации. Без протокола реагирования продукт использует PHQ-8.
6. **Прогресс паттерна** — интенсивность и доля избегания, не частота эпизодов.
7. Любые сетевые вызовы, хранение данных или Telegram-бот — только после юридической
   проверки (152-ФЗ: сведения о здоровье — специальная категория; локализация;
   трансграничная передача в зарубежный API).

## Команды

```bash
python -m pip install -e ".[dev]"
pytest -q
python examples/demo.py
```

Перед каждым коммитом: тесты зелёные, новая логика покрыта тестами.

## Структура

```
src/mbc/
  measures.py         шкалы, пороги, источники
  scoring.py          суммарный балл, проверка ответов, пропуски
  reliable_change.py  SEM, порог RCI, порог по своей выборке, классификация изменения
  status.py           статус по одной шкале и по двум (флаги NHS)
  trajectory.py       сигнал траектории, правило уровня 4а
  safety.py           PHQ-9, пункт 9
  triggers.py         карта триггеров, паттерны, недельная динамика
  hypotheses.py       контракт гипотез ИИ
  report.py           отчёт для терапевта: светофор, статус, паттерны, телесные факторы
  discrepancy.py      слой расхождений: самоотчёт × CGI-S терапевта, темы для разговора
tests/                pytest, 360 тестов
examples/demo.py      синтетический клиент
prompts/              шаблон промпта ИИ-слоя
docs/                 гайд интервью, практика, реестр методик, мастер-документ, спецификация
research/oasis_stage0 пакет этапа 0 адаптации OASIS
```
